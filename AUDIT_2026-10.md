# VEILOS audit: before the hardware abstraction layer (2026-10-28)

Scope: all of `src/` (~60k lines), read with a focus on the low-level layers a multi-device HAL
will sit on. Method: grep sweeps for stub markers, a build with every `#![allow(dead_code)]`
stripped, module reachability analysis, and a manual read of boot, memory, interrupts,
syscall, SMP, loader, PCI, AHCI, VFS/FAT, GPU and network code.

Items are ordered by how much they will block or destabilise HAL work. A `file:line` is the
best anchor at time of writing.

---

## Tier 0: architectural blockers for a multi-device HAL

These are design gaps rather than bugs. Each one hard-codes "exactly one device" or
"exactly one CPU doing kernel work", which is what the HAL wants to remove.

### 0.1 No device model; PCI is a throwaway list

> **Status (2026-10-28): mostly done.** `pci.rs` is now a registry that is scanned once at
> boot. It provides config read/write, BAR sizing (including 64-bit BARs), a capability walk
> that decodes MSI/MSI-X info, and command-register helpers. All 6 rescans now use the
> registry. AHCI and virtio-net enable decode and bus-master themselves. Still open: ECAM
> (PCIe extended config), and actually programming MSI/MSI-X. The IOAPIC/LAPIC groundwork
> for MSI is now in (0.4).

- `pci::scan_buses()` returns a local `Vec`. It is never stored, so 6 call sites rescan the bus
  independently (`main.rs:259`, `graphics.rs:78`, `gpu_driver.rs:541`, `stability.rs:490`,
  `distribution.rs:116`). Each rescan also `println!`s every device.
- There is no config-space **write**, so drivers cannot set bus-master, memory-enable or
  interrupt-disable themselves. They rely on firmware having done it.
- There is no BAR sizing, and 64-bit BARs are not handled: `read_bar() & !0xF` drops the
  upper half. Drivers guess the sizes instead ("Assume 256 MiB VRAM", `gpu_driver.rs:560`).
- The capability list is never walked, so there is no MSI/MSI-X and no PCIe extended config
  (ECAM/MCFG).
- There is no driver registry or binding: each subsystem does its own `class == 0x03` style
  matching.

### 0.2 Single-GPU, single-display assumption everywhere
- `ui::SCREEN_W/SCREEN_H` are compile-time `1024×768` (`ui.rs:7-8`). Stride is assumed equal
  to width (`graphics.rs`).
- `graphics::probe_gpu()` writes Bochs BGA ports unconditionally, then treats BAR0 of the
  **first** display-class device as a linear framebuffer. On Intel/AMD/NVIDIA hardware, BAR0
  is the MMIO register block, so pixel writes would land in device registers.
- `gpu_driver` registers every GPU as a BGA-model device. It assumes BAR1 is VRAM, which is
  not true on stdvga/bochs-display. All submission goes through `primary()` (index 0,
  `gpu_driver.rs:593`).
- The bootloader's framebuffer info (VBE/GOP) is never used.

### 0.3 Storage stops at the first filesystem
- `ahci.rs:184` onward probes the next filesystem only `if VFS.mounts.is_empty()`. As a
  result, the second disk or second partition is never mounted. NTFS is the exception: it is
  always probed, and mounts on top.
- Only MBR partition entry #1 is read (`bytes[450..458]`). There is no GPT and no other
  partitions.
- VFS resolves a path to the **first** mount that matches, not the longest prefix. A root
  mount `/` therefore shadows every mount added after it (`vfs.rs` `path_under_mount`).
- The API is whole-file only (`read_file -> Vec<u8>`). There are no handles, seek, stat,
  mkdir or rename, and no block or page cache.
- The global `VFS` mutex is held across all disk I/O, which serialises every FS operation
  system-wide.

### 0.4 Interrupt routing is legacy-PIC only

> **Status (2026-10-28): mostly done.**
> - `ioapic.rs` reads the I/O APICs and ISA overrides from the MADT and routes the PIT,
>   keyboard and mouse through the I/O APIC to the BSP. It then masks the 8259; if there is
>   no I/O APIC it stays on the 8259. `interrupts::{mask_irq, unmask_irq}` and the ISRs' EOI
>   work on either controller.
> - `time.rs` calibrates the TSC against PIT channel 2 and provides `delay_us`/`delay_ms`,
>   `Deadline`, `spin_until` and `now_us`/`now_ns`.
> - The LAPIC timer is calibrated the same way (`smp::lapic_timer_ticks_per_ms()`), and APs
>   now tick at a real 1 ms.
> - AHCI, virtio-net, PS/2 and SMP bring-up use wall-clock timeouts instead of loop counts.
> - Still open:
>   - PCI INTx routing (needs the ACPI `_PRT`, i.e. AML) and MSI programming, so drivers still
>     poll.
>   - The BSP system tick is still the PIT (moving it to the LAPIC timer belongs with
>     preemption, step 5).
>   - No HPET.
- Only the 8259 PIC is used. There is no IOAPIC programming and no MSI, so device IRQs cannot
  be routed to other CPUs.
- In practice every driver (AHCI, virtio-net) polls.
- The BSP timebase is the PIT. The AP LAPIC timer is uncalibrated (`0x40000` "~1 ms at
  1 GHz", `smp.rs`).
- Driver timeouts are loop-iteration counts (`ahci.rs`, `virtio_net.rs:196`), so their real
  length depends on CPU speed and accelerator.

### 0.5 No preemption, no per-process address space
- A user process runs **inside an executor poll** (`loader.rs` `process_execution_task` →
  `launch_into_usermode`). The async executor is frozen until that process exits.
- While a process runs, the whole desktop is painted from the **timer ISR**
  (`interrupts.rs:~900-990`).
- The scheduler is bookkeeping only. `QUANTUM_EXPIRED` is set but never consumed outside
  `scheduler.rs`, and `handle_expiry` has no caller. There is no context switch.
- APs only accept whole ring-3 processes from `AP_WORK_QUEUE`. All kernel work (GUI, network,
  FS) runs on the BSP.
- Every process gets the kernel's CR3 (`process.rs:89`), so there is one shared address space.
  "Security Mode" isolation is only the U/S page bit: any ring-3 process can read any other
  process's pages. PE images that share a preferred base collide (hence the remap-on-collide
  logic in `memory.rs`).

## Tier 1: correctness bugs (crashes, corruption, security holes)

> **Status (2026-10-28):**
> - **Fixed: items 1, 2, 3, 4, 5, 13.** Each CPU now has a `PerCpu` block reached via
>   `swapgs`, and APs have separate boot stacks. `syscall_entry` was rewritten so it no
>   longer touches R15 or the user stack. The new `interrupts::syscall_stack_arg()` gives
>   handlers stack args (wired into CreateWindowExW). `cpu_index()` now uses an APIC-ID
>   lookup table.
> - **Partly fixed: item 6.** The non-canonical `sysret` guard and SFMASK DF/TF/AC/NT
>   masking are in. Interrupts are still off for the whole syscall: re-enabling them needs
>   item 8 (ISR heap use) fixed first.
> - **Also fixed:**
>   - APs never enabled SSE (CR4.OSFXSR), so any SSE instruction on an AP raised `#UD`.
>   - PS/2 mouse init lost every ACK to the IRQ12 ISR.
>   - PIC mask updates spun against the timer ISR.
> - **Fixed in step 4 (memory): items 7 and 8.**
>   - `map_page_checked` no longer frees the frame it replaces.
>   - `deallocate_frame` now refuses anything that isn't usable RAM, and double frees.
>   - The heap is IRQ-safe: every alloc/free runs with interrupts off.
>   - Zombie/thread reaping moved out of the timer ISR into `scheduler::reaper_task`.
>   - Painting from the ISR is still there (step 5).
> - **Also found and fixed in step 4:**
>   - AHCI gave its 32 command tables (8 KiB) a single 4 KiB frame, so slots 16-31 pointed
>     into a foreign frame. Port memory is now one 12 KiB contiguous DMA block.
>   - virtio-net's 12 KiB virtqueues were statics whose pages were only virtually
>     contiguous. They now come from `DmaRegion`.
>   - The frame allocator could hand out frames below 1 MiB, including the AP trampoline
>     page at 0x8000. Low memory is now reserved.
>   - Item 6's remaining half (re-enabling IF during syscalls) is now unblocked on the heap
>     side. It still needs the ISR paint path gone (step 5).

| # | Where | Problem |
|---|---|---|
| 1 | `smp.rs:742` + `smp.rs:97` | **AP boot stack and AP syscall stack are the same memory.** The trampoline is given `syscall_stack_top(i)`, and `KERNEL_GS_BASE` points at the same top. When a process on an AP makes a syscall, `syscall_entry` sets RSP to that top and overwrites `park_and_wait_for_work` / `launch_into_usermode` frames. When `return_from_usermode()` later returns through them, those frames are already corrupted. Expect crashes when a process exits on an SMP boot. |
| 2 | `smp.rs:85` | `PERCPU_SYSCALL_STACKS` is an immutable `static` with no `UnsafeCell` but is written to as a stack. That is UB. It works only because `--omagic` makes everything RWX. `gdt.rs` already fixed the same bug for the exception stacks. |
| 3 | `interrupts.rs:189` | `syscall_entry` does `mov r15, rsp` and never saves or restores the user's R15. R15 is **non-volatile** in the Windows x64 ABI, so every syscall silently corrupts it in MSVC code. |
| 4 | `interrupts.rs:206-207` | In ring 0, `push r12/r13` go onto the **user-supplied RSP** before switching stacks. A malicious or garbage RSP makes the kernel write to an arbitrary address, including kernel memory. |
| 5 | `interrupts.rs` / `loader.rs:~1474` thunks | Only 4 args are forwarded (R10, RDX, R8, R9). Win32 args 5+ live on the user stack, and the user RSP is never passed to the dispatcher. `CreateWindowExW` x/y/w/h, `CreateFileW` and others are therefore unreachable (acknowledged at `win32_user.rs:998,1048`, `subsystem.rs:468,798`). |
| 6 | `interrupts.rs` syscall path | IF stays 0 for the **entire** syscall (SFMASK, never re-enabled). Long syscalls block the timer, keyboard and mouse. `sysretq` is also used with an unchecked RCX (the non-canonical-RIP #GP-in-ring-0 issue). |
| 7 | `memory.rs:77-83` | `map_page_checked` on an existing mapping to a *different* frame **frees the old frame**. If the old mapping was MMIO, a kernel page, or another process's page, that physical address goes onto the free list and is later handed out as RAM. |
| 8 | `scheduler.rs:796`, `interrupts.rs:956` | Heap work in ISR context. The timer ISR calls `reap_zombies()` every 1000 ticks (unmap, `deallocate_frame` Vec push) and `paint_desktop()` while a process runs. `LockedHeap` is not IRQ-safe, so if the interrupted kernel code holds the heap lock, the CPU deadlocks. The comment on `allocator::heap_usage` claims interrupts are off while the allocator lock is held, but that is only true inside that one function. |
| 9 | `task/executor.rs:30,116` | The waker does `push(...).expect("Task queue is full")`. Duplicate wakes push duplicate IDs (there is no dedupe), so a busy re-waking task can panic the kernel from inside a waker (possibly from an ISR). |
| 10 | `ahci.rs:116-122` | 32 command tables × 256 B = 8 KiB placed in **one** 4 KiB frame. Slots 16-31 would overwrite whatever frame comes next. This is latent today only because I/O is synchronous and slot 0 is always free. |
| 11 | `ahci.rs:260` | `unsafe impl Sync for AhciBlockDevice`, but `read_sectors(&self)` does `&mut *self.port` and uses one shared bounce buffer with no lock. Two concurrent callers (another CPU, or an ISR path) corrupt each other's I/O. |
| 12 | `gpu_driver.rs:331` | `BitBlt` uses `copy_nonoverlapping` for overlapping src/dst, which breaks scrolling. Bounds are clamped against `SCREEN_W` instead of `fb.width`. `UploadSurface` dereferences a caller-supplied `src_ptr` without `user_ptr_ok`. |
| 13 | `loader.rs:838` | `current_exec_cpu() = apic_id % 8`. APIC IDs are not dense on real hardware (0, 2, 4… or >8), so two CPUs can share one long-jump slot and lock table. `smp.rs` indexes by `cpu_index` while the loader indexes by APIC ID, which is inconsistent. |
| 14 | `loader.rs:1000` | When the lock-tracking table is full, the guard reuses slot 7, overwriting another live entry. Its `Drop` then clears that entry. |
| 15 | `memory.rs` `allocate_frame` | When a region ends on a non-page boundary, `advance_to_next_region(next_phys+1)` can re-select the same region and hand out a frame that extends past its end. Bootloader regions are usually aligned, so this is low impact. |
| 16 | `tls.rs:283` | `CertStore` defaults to `trust_all: true`, so any certificate is accepted unless pins are loaded. |
| 17 | `tls.rs:91`, `encryption.rs:226-262` | There is **no CSPRNG** in the kernel. The TLS RNG is xorshift64 seeded from the PIT, and is declared `CryptoRng`. Non-password keys are `SHA256(counter‖counter‖feature)`, which makes them predictable. |

## Tier 2: inefficiencies

- **Serial logging in hot paths.** Every syscall logs 2 lines (`interrupts.rs:335,356`), and
  the loader logs every IAT entry. `_serial_print` disables interrupts while writing. On real
  hardware at 115200 baud this is roughly 7 ms per 80-character line, so each syscall would
  cost more than 10 ms. QEMU hides this. Gate the logging behind a level or ring buffer.
  Even under QEMU it shows up: with gui_test.exe running on an AP (≈100k syscalls/run), the
  BSP's GUI task fights it for the serial lock and drops to ~8000 Mcycles per frame. The
  desktop stops responding until the app exits.
- ~~**The framebuffer is mapped uncached**~~ **Fixed (step 4):** `smp::init_pat` programs
  PAT entry 1 as write-combining on every CPU. The framebuffer, user VRAM mappings and NT
  `PAGE_WRITECOMBINE` now use it. TCG doesn't model memory types, so the gain only shows
  on real hardware.
- **Full-scene repaint for any change** (`main.rs` `gui_refresh_task`). Only the clock and
  cursor have partial paths. With no damage tracking, one blinking caret repaints and
  re-uploads the whole screen.
- **The timer ISR paints the entire desktop** at 60 Hz while a process runs. That is
  milliseconds of work with IF=0.
- **FAT has no FAT cache.** `fat32.rs:111` `get_next_cluster` does one sector read per
  cluster hop, so reading an N-cluster file costs 2N disk commands. There is no block cache
  in any filesystem.
- **AHCI moves 8 sectors per polled command** through a 4 KiB bounce buffer. The PRDT
  supports 8 entries and could take the caller's pages directly.
- **The PCI bus is rescanned 6×**, printing everything each time (see 0.1).
- **Win32 CRT math is done by syscalls** (`subsystem.rs:0x9501+`), each a ring transition
  plus 2 serial lines. The math is also software approximation (Bhaskara sine ≈0.1% error,
  14-bit Newton sqrt) even though SSE2 `sqrtsd` is available. `ceil`/`floor` via `as i64`
  break above 2^63.
- **Win32 `malloc` is a syscall per allocation** (`subsystem.rs:1270`). It maps whole 4 KiB
  pages plus a guard page per call, from a global VA bump pointer shared by all processes
  that never reclaims VA. `malloc(16)` costs 8 KiB of VA and 4 KiB of RAM.
- ~~**`memory::deallocate_frame`** does an O(n) linear double-free scan over a `Vec`~~
  **Fixed (step 4):** the frame allocator is now a bitmap with O(1) free and double-free
  checks, no heap use, and contiguous runs (`allocate_contiguous`, `DmaRegion`).
- **The `println!` VGA text writer** is still written to after switching to the BGA
  framebuffer. That is invisible work.

## Tier 3: stubbed or half-implemented (claims to work, doesn't)

### Storage / persistence
- **FAT16 has no `write_file`/`delete_file`** (`fat16.rs`; it uses the trait default
  `WriteError`). The default run config (`fat:rw:storage` in `Cargo.toml:79` and
  `run_dual.ps1:51`) is QEMU vvfat, which defaults to FAT16 for hard disks. So **nothing
  persists in the default setup**: users (`/etc/users.vdb`), last user, scheduler profiles,
  clipboard history, editor saves, checkpoints, the key ledger.
- **FAT32 writes are root-directory, 8.3 names only** (`fat32.rs:514-560`). Every
  `/etc/...`, `/tmp/...` and `/net/...` write fails even on FAT32. There is no mkdir, which
  the terminal works around with `.veilos_dir` marker files.
- **NTFS and exFAT are read-only.**
- `ide.rs` is never initialised; its call is commented out in `main.rs`.

### Kernel services
- **Adaptive scheduler never learns.** `on_process_exit` is called only from `game_sdk.rs`,
  never from `loader::on_process_exit`. Profiles get no session data for normal apps.
- **Security Mode is not enforced.** The default `SyscallFilter::permissive()`
  (`process.rs`) and capability checks exist only in encryption, network, TLS, VNR and the
  game SDK. Win32 file, memory, window and process syscalls are unchecked.
- **Performance Mode does nothing.** `policy::run_task` (the ring-0 `jmp` path) has no
  callers, and `gdt::drop_to_ring_3` is only called from it. Switching modes changes
  capability bits and a GPU submit path, nothing else.
- `nt_thread.rs:356`: the thread "register swap" is stubbed. Threads are a state machine
  only.
- `nt_objects.rs:693,872,908,949`: `NtOpenEvent/Mutant/Semaphore/Section` by name are
  unimplemented.
- `encryption.rs:493`: `cen_purge_ledger` is unimplemented.
- `audio.rs`: only a volume variable exists. There is no driver.
- `shell.rs:510`: there is no ACPI. Power-off only works on emulators.

### Drivers
- **Networking:** only legacy virtio-net (`network.rs:879`) exists. `Cargo.toml:83` attaches
  an **e1000**, so `cargo run` has no network. Only `run_dual.ps1` works. Only one NIC is
  supported, and it is polled.
- **GPU 3D:** every 3D command is silently dropped (`gpu_driver.rs` `execute_command`), and
  `gfx_api` emits placeholder SPIR-V headers (`gfx_api.rs:678-748`). `Present` is a no-op.
- **Compositor:** `COMPOSITOR.tick()` is disabled (`main.rs:597`), but `win32_user.rs` and
  `subsystem.rs` still create compositor surfaces. Check whether Win32 surfaces are drawn by
  anything.

### Win32 layer
- **256 functions** in `subsystem.rs` return a constant. Dangerous ones:
  - `ReadFile → FALSE` ("no file I/O yet").
  - `LockResource → 1`: a pointer the app will dereference, causing a guaranteed crash.
  - `LoadLibrary → 1` (fake HMODULE).
  - `WaitForSingleObject` always signalled.
  - `GetLastError` is always 0.
  - `CreateProcessW → FALSE`.
  - `GetCurrentDirectoryW`/`GetSystemDirectoryW → 0`.
  - `DuplicateHandle` returns TRUE without duplicating.
- `subsystem.rs:363-375,1417`: critical sections and SRW locks always succeed ("single
  threaded"). These become data races as soon as threads are real.
- `toolchain.rs:216,297`: the fd is always 3, and the RTC returns ticks.

### Distributed / misc
- `distributed.rs:2277` `capture_framebuffer`: the `gpu_mode` branch does nothing. The
  fallback samples the **VGA text buffer at 0xB8000**, not the real framebuffer, so RDP
  viewers see text-mode cell colours. The August audit's "gradient" issue is changed but not
  fixed.
- `distribution.rs:399-402,545`: remote update fetch is not implemented.
- `app_repo.rs:432`: logs intent and returns success without doing the work.
- `users.rs:519`: placeholder `Ok(())`.
- `anticheat.rs:196`: `NtQuerySystemInformation` returns "not implemented" for most classes.

## Tier 4: dead or effectively-unused code

24 files carry a crate-level `#![allow(dead_code)]`, which hides most of this. With those
removed, rustc reports 44 dead items. Most are unused constants. Notable ones are
`desktop::setup_desktop_phase`, `nt_objects` `next_id`, `fat16::total_sectors`,
`ntfs::extract_filename` and `compositor` `surface_id`.

The bigger problem is modules that are compiled, initialised at boot, and then never called:

| Module | Lines | Only external use |
|---|---|---|
| `ui_runtime.rs` | 1907 | `is_snapshot_key` (from `vscript`) |
| `render2d.rs` | 2179 | `isqrt_u`, `demo` |
| `gfx_api.rs` | 749 | `init()` |
| `tls.rs` | 622 | `init()`. Nothing opens a TLS session. |
| `app_repo.rs` | 475 | `init()` |
| `game_sdk.rs` | 470 | `init()` |
| `ide.rs` | 118 | nothing |
| `task/simple_executor.rs` | 57 | nothing |
| `policy::run_task`, `gdt::drop_to_ring_3` | — | nothing (see Tier 3) |
| `scheduler` `handle_expiry`/`QUANTUM_EXPIRED`/`offload_task`/`dispatch_batch` | — | nothing outside the module |

Also:
- `scratch/vscript.rs` is a stale copy of `src/vscript.rs`.
- `audit_report.md` is the previous audit. Its `free()` item is fixed, and its EPT item now
  maps frames, though it never issues INVEPT and never frees those frames. Its pkgmgr item
  now returns honest errors. Its math item is improved but still approximate. Its
  framebuffer-capture item is still wrong (see Tier 3).

## Suggested order before starting the HAL

1. **PCI/device core:** a global device registry, config write, BAR sizing and 64-bit BARs,
   a capability walk with MSI/MSI-X, and bus-master enable. This replaces all 6 rescans
   (0.1).
2. **Per-CPU infrastructure:** a real per-CPU block via `GS` and `swapgs`, and separate
   boot/syscall/interrupt stacks per CPU (fixes 1.1, 1.2, 1.13). Rewrite `syscall_entry` to
   preserve R15, avoid touching the user stack, pass the user RSP for stack args, and
   re-enable IF (fixes 1.3-1.6).
3. **Interrupts and time:** IOAPIC and LAPIC timer calibrated against PIT/HPET, a TSC
   timebase, and a `delay_us()` so drivers stop counting loop iterations (0.4).
4. **Memory:** a contiguous/DMA frame allocator for driver rings, fix `map_page_checked`
   freeing foreign frames (1.7), make the heap IRQ-safe or ban allocation in ISRs (1.8), and
   map framebuffers as WC.
5. **Execution model:** per-process CR3, kernel threads, and timer-driven preemption, so
   user processes no longer block the executor and the ISR stops painting (0.5).
6. **Block layer:** a per-device lock or request queue, GPT plus all partitions on all
   disks, longest-prefix mounts, a FAT cache, and FAT16/FAT32 subdirectory writes (0.3,
   Tier 3).
7. Then build the HAL on top. The GPU and display path (0.2) is where most of the HAL work
   will land, so the items above keep it from inheriting single-device assumptions.
